# Equipper

Интеллектуальный организатор медиафайлов по устройствам и приложениям на основе алгоритма группировки.

## Описание

Equipper анализирует медиафайлы и автоматически организует их по логике камерных приложений (Photos, Halide, Blackmagic Camera, Moment, Filmic) и устройствам. Проект использует современную архитектуру с разделением обязанностей между детекторами, группировщиками и организатором файлов.

## Алгоритм работы

### Трехэтапная обработка

Equipper использует современный алгоритм группировки, состоящий из трех основных этапов:

#### Этап 1: Сканирование и группировка файлов

**Принцип группировки:**
- Анализирует все медиафайлы в директории (.HEIC, .JPG, .PNG, .DNG, .MOV, .AAE)
- Извлекает базовые имена файлов для группировки связанных файлов
- Создает группы файлов по связям и определяет принадлежность к приложениям

**Логика извлечения базовых имен:**
```
IMG_E7256.HEIC → базовое имя: "7256"
IMG_3431.AAE   → базовое имя: "3431" (группируется с IMG_3431.*)
IMG_7256.HEIC  → базовое имя: "7256"
A001_08041410_C001.MOV → базовое имя: "A001_08041410_C001"
```

**Пример группировки:**
```
Группа "7256":
├── IMG_7256.HEIC     (основной файл)
├── IMG_E7256.HEIC    (обработанный вариант)
└── IMG_7256.AAE      (метаданные редактирования)
```

#### Этап 2: Создание структуры устройств

**Определение устройств:**
- Извлекает EXIF метаданные из основных файлов групп
- Создает папки устройств на основе Make/Model из EXIF
- Нормализует названия iPhone (iPhone14,3 → iPhone 13 Pro Max)
- Создает подпапки для приложений в каждом устройстве

**Структура папок:**
```
Apple iPhone 13 Pro Max/
├── (корень устройства - для приложения Фото)
├── Halide/
├── Blackmagic Camera/
├── Moment/
└── Filmic/
```

#### Этап 3: Перемещение файлов группами

**Принцип перемещения:**
- Перемещает файлы целыми группами (сохраняет связи)
- Определяет папку назначения на основе классификации группы
- Файлы без EXIF данных попадают в основное устройство

### Классификация файлов по приложениям

iPhone-приложения не оставляют уникальной подписи в EXIF (поле Software
содержит только версию iOS), поэтому Photos и Halide различаются по
**сигнатуре файлов в группе**. Ключевые дискриминаторы Photos.app:

- **AAE-сайдкар** (`IMG_xxxx.AAE`) — пишется только при правке в Photos.app,
  Halide такие сайдкары не создаёт.
- **MOV-видео** (`IMG_xxxx.MOV` или `IMG_Exxxx.MOV`) — компонент Live Photo,
  Halide MOV не создаёт.

Если в группе есть AAE или любой MOV — это Photos, даже если другие файлы
по форме совпадают с сигнатурой Halide. Halide-классификация применяется
только к группам **без AAE и без MOV**.

#### 1. Приложение Фото (Photos)

**Обычное фото:**
```
IMG_7257.HEIC (одиночный)
→ Назначение: корень устройства
```

**Apple ProRAW (Камера в режиме ProRAW):**
```
IMG_7258.DNG (одиночный, ~25 МБ)
→ Назначение: корень устройства
```
Одиночный DNG — это ProRAW из стандартной Камеры iOS, а не Halide.
Halide RAW всегда идёт парой с HEIC (см. ниже).

**Live Photo (без правки):**
```
IMG_7256.HEIC + IMG_7256.MOV (общий ContentIdentifier в EXIF)
→ Назначение: корень устройства
```

**Обычное фото, отредактированное в Photos:**
```
IMG_7256.HEIC + IMG_E7256.HEIC + IMG_7256.AAE
├── Оригинал: IMG_7256.HEIC
├── Результат правки: IMG_E7256.HEIC
└── Сайдкар правки: IMG_7256.AAE
→ Назначение: корень устройства
```
Без AAE-сайдкара эта же сигнатура (`HEIC + IMG_E.HEIC`) считается
Halide Portrait — поэтому AAE здесь критичен.

**Live Photo, отредактированное в Photos:**
```
IMG_7256.HEIC + IMG_7256.MOV + IMG_E7256.HEIC + IMG_E7256.MOV + IMG_7256.AAE
→ Назначение: корень устройства
```

**ProRAW, отредактированное в Photos:**
```
IMG_7258.DNG + IMG_E7258.JPG + IMG_7258.AAE
├── Оригинал ProRAW: IMG_7258.DNG
├── Результат правки (JPEG): IMG_E7258.JPG
└── Сайдкар правки: IMG_7258.AAE
→ Назначение: корень устройства
```
Photos.app экспортирует правку ProRAW как JPEG, не пересохраняя DNG.

**Обработанный файл без оригинала:**
```
IMG_E7258.JPG (без соответствующего IMG_7258.HEIC/DNG)
→ Назначение: корень устройства
```

#### 2. Halide

Halide классифицируется только когда в группе **нет ни AAE, ни MOV**.

**Halide RAW:**
```
IMG_7257.DNG + IMG_7257.HEIC
├── RAW файл: IMG_7257.DNG
└── JPEG превью: IMG_7257.HEIC
→ Назначение: папка Halide
```

**Halide Portrait:**
```
IMG_7256.HEIC + IMG_E7256.HEIC (без MOV, без AAE)
├── Оригинал: IMG_7256.HEIC
└── Обработанный портрет: IMG_E7256.HEIC
→ Назначение: папка Halide
```

#### 3. Blackmagic Camera

**Определение через EXIF:**
- Поле Software содержит "blackmagic"
- Все файлы группы → папка Blackmagic Camera

**Пример:**
```
A001_08041410_C001.MOV (Software: "Blackmagic Cam 2.3.000047")
→ Назначение: папка Blackmagic Camera
```

#### 4. Moment

**Определение только через EXIF:**
1. **EXIF Software:** "moment" в поле Software
2. **EXIF Make:** "Moment" в поле Make

**Пример:**
```
IMG_7259.DNG (Software: "Moment Pro Camera")
→ Назначение: папка Moment
```

#### 5. Filmic Pro

**Определение только через EXIF:**
1. **EXIF Make:** "Filmic" в поле Make  
2. **EXIF Software:** "filmic" в поле Software

**Пример:**
```
08042025_141023.MOV (Software: "Created with Filmic Legacy 6.23.1 build 136760")  
→ Назначение: папка Filmic
```

### Специальные случаи обработки

#### AAE файлы (сайдкары правки Photos.app)

AAE — это plist-сайдкар, который Photos.app создаёт **только** при
редактировании. Внутри лежит `adjustmentBaseVersion` / `adjustmentData`
с инструкциями правки. Halide такие файлы не пишет.

**Следствие для классификации:** наличие AAE в группе → Photos. AAE
сам по себе перемещается в той же папке, что и его группа.

#### Файлы без EXIF данных

**Обработка:**
- Файлы от приложений (без Make/Model в EXIF) → основное устройство
- Классификация по логике приложений сохраняется
- Назначаются в первое найденное устройство или дефолтное

### Режимы работы

Скрипт автоматически определяет режим по содержимому переданной директории.
В обоих режимах действуют общие правила относительно сохранения папок:

- **Целевая папка (та, что передана аргументом) никогда не удаляется** —
  даже если после обработки она оказалась пустой.
- **Подпапки-пакеты в Режиме 2 сохраняются** как контейнеры экспортов,
  даже если внутри осталась только одна устройство-папка.
- **Промежуточные пустые подпапки удаляются** — например, если внутри
  устройства не оказалось файлов из Halide/Blackmagic, эти служебные папки
  не создаются (или удаляются после обработки).
- **Системный мусор вычищается** — `.DS_Store`, `Thumbs.db`, `desktop.ini`,
  `._*` (AppleDouble) удаляются перед удалением пустых папок и не мешают
  их удалению.

#### Режим 1: Одна папка с файлами

```bash
equipper ~/Pictures/Camera_Roll
```

Срабатывает, когда **в корне переданной папки лежат медиафайлы** и нет
дочерних папок с медиа. Все файлы обрабатываются как одна группа,
а структура устройств/приложений создаётся **прямо внутри** этой папки.

```
Camera_Roll/                       ← целевая папка, остаётся
├── Apple iPhone 13 Pro Max/       ← создаётся в целевой папке
│   ├── IMG_7256.HEIC
│   └── Halide/
│       └── IMG_7257.DNG
└── Fujifilm X-E5/
    └── _DSF4086.RAF
```

#### Режим 2: Папка с подпапками-пакетами

```bash
equipper ~/Pictures/Multiple_Exports
```

Срабатывает, когда **дочерние папки содержат медиафайлы** (например,
выгрузки с разных карт или сессий съёмки). Каждая подпапка обрабатывается
**независимо**, и устройство-папки создаются **внутри** соответствующей
подпапки. Контейнерные подпапки сохраняются как batch-группировка.

```
Multiple_Exports/                  ← целевая папка, остаётся
├── DJI_001/                       ← пакет, остаётся как контейнер
│   └── DJI Mini 5 Pro/            ← устройство внутри пакета
│       ├── DJI_..._0001_D.MP4
│       └── DJI_..._0001_D.SRT
└── DJI_002/                       ← пакет, остаётся как контейнер
    └── DJI Osmo Action 5 Pro/
        ├── DJI_..._0009_D.DNG
        └── DJI_..._0009_D.JPG
```

Если в той же целевой папке одновременно есть и файлы в корне, и дочерние
пакеты, корневые файлы обрабатываются отдельным проходом — без захода
в уже обработанные подпапки.

### Поддерживаемые форматы

**Фотографии:** `.HEIC`, `.HEIF`, `.JPG`, `.JPEG`, `.PNG`, `.TIF`, `.TIFF`

**RAW (по производителям):**
- Adobe / Apple Halide / Leica / Pentax / Ricoh / Sigma (новые): `.DNG`
- Fujifilm: `.RAF`
- Sony: `.ARW`, `.SR2`, `.SRF`
- Canon: `.CR2`, `.CR3`, `.CRW`
- Nikon: `.NEF`, `.NRW`
- Olympus / OM System: `.ORF`
- Panasonic: `.RW2`, `.RAW`
- Leica: `.RWL`
- Pentax: `.PEF`
- Hasselblad: `.3FR`, `.FFF`
- Phase One: `.IIQ`
- Sigma (старые): `.X3F`
- Samsung: `.SRW`
- Прочие: `.MRW`, `.MEF`, `.MOS`, `.ERF`, `.KDC`, `.DCR`

**Видео:** `.MOV`, `.MP4`, `.M4V`, `.INSV`, `.LRV`, `.THM`

**Метаданные / sidecar:** `.AAE`, `.XMP`, `.SRT` (телеметрия дронов DJI),
`.LRF` (low-res preview Osmo Action / дронов)

### Нормализация устройств

Производители приводятся к маркетинговому написанию независимо от регистра
в EXIF (`FUJIFILM` → `Fujifilm`, `NIKON CORPORATION` → `Nikon`,
`OM Digital Solutions` → `OM System`, `SZ DJI Technology Co., Ltd.` → `DJI`).

Технические идентификаторы моделей переводятся в маркетинговые имена:
- Apple: `iPhone14,3` → `iPhone 13 Pro Max` (полный словарь поколений 6–15)
- DJI: `FC9313` → `DJI Mini 5 Pro`, `AC004` → `DJI Osmo Action 5 Pro`,
  `FC8482` → `DJI Mini 4 Pro`, `FC7303` → `DJI Mini 3 Pro`,
  `AC003` → `DJI Osmo Action 4`, `AC002` → `DJI Osmo Action 3`

## Безопасность

⚠️ **Внимание:** Скрипт перемещает файлы без создания резервных копий
- Рекомендуется создать резервную копию перед использованием
- Файлы не изменяются, только перемещаются и группируются
- Пустые папки автоматически удаляются (см. правила в разделе «Режимы работы»)
- Системные файлы (`.DS_Store`, `Thumbs.db`, `desktop.ini`, `._*`)
  удаляются как часть очистки

## Архитектура

### Модульная структура (src-layout)
```
equipper/
├── src/
│   └── equipper/
│       ├── __init__.py      # Экспорт публичного API (FileOrganizer)
│       ├── cli.py           # Точка входа CLI (entry point: equipper.cli:main)
│       ├── organizer.py     # Основная логика FileOrganizer
│       ├── detectors.py     # Классификация и группировка
│       └── constants.py     # Константы приложений и форматов
├── pyproject.toml           # Конфигурация проекта
├── requirements-dev.txt     # Зависимости для разработки
└── README.md                # Документация
```

### Основные классы

**FileOrganizer** - центральный класс организации с поддержкой двух режимов работы  
**OrganizationPipeline** - координатор этапов обработки файлов  
**FileGrouper** - группировка файлов по связям с EXIF анализом  
**FileGroup** - представление группы связанных файлов  
**FileTypeDetector** - определение типов медиафайлов по расширениям  
**PhotosAppFileDetector** - сложная логика определения файлов из приложения Фото  
**BlackmagicDetector** - специализированный детектор Blackmagic через EXIF  
**HalideDetector** - определение файлов Halide по характерным признакам  

## Разработка

### Качество кода
Проект использует Ruff для форматирования и линтинга:
```bash
# Проверка кода
ruff check .

# Форматирование
ruff format .
```

### Запуск тестов
```bash
# Создание тестовых файлов
mkdir tmp
cd tmp
touch IMG_3431.HEIC IMG_E3431.HEIC IMG_3431.AAE

# Тестирование
cd ..
equipper tmp                     # после pip install -e .
python -m equipper.cli tmp       # как модуль (без установки скрипта)
```

### Добавление новых приложений

1. Добавить константу в `constants.py`:
```python
class AppNames:
    NEW_APP = "New App"
```

2. Расширить логику в `detectors.py`:  
```python
def _determine_group_app_type(self, group):
    # Добавить проверки для нового приложения
    if self._is_new_app_file(group):
        return AppNames.NEW_APP
```

## Особенности реализации

### Обработка ошибок
- Все детекторы инициализируются с обработкой ошибок и fallback механизмами
- EXIF операции обернуты в try/catch блоки для предотвращения сбоев
- Файлы без EXIF данных корректно обрабатываются и назначаются дефолтному устройству

### Нормализация устройств Apple
- Поддержка полного спектра iPhone моделей с iPhone 6 до iPhone 15 Pro Max
- Автоматическое преобразование технических идентификаторов (iPhone14,3 → iPhone 13 Pro Max)
- Фильтрация приложений от реальных устройств в EXIF данных

### Производительность
- Batch операции для создания папок и перемещения файлов
- Эффективная группировка файлов по базовым именам
- Минимальное количество EXIF операций через кэширование в группах
